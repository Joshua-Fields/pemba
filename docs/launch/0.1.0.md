## Release summary — proposed GitHub Release text

**DRAFT: use only after T7.14–T7.16 and human approval of this text in T7.17.**

pemba 0.1.0 is an embedded, Zanzibar-style authorization engine in Rust with Python
bindings. Its headline feature is transactional relationship writes: create an app
row and its permissions in the same SQLite or Postgres transaction, and let them
commit or roll back together.

Define a policy using a strict subset of SpiceDB's schema language, store
relationships in your database, and check permissions or look up resources and
subjects in-process. Rust crates, a CLI, Python bindings, memory/SQLite/Postgres
stores and explain traces are included. Database integration is synchronous.

Start with the [installation guide](https://joshua-fields.github.io/pemba/docs/guides/installation.html)
and the tested [commit/rollback tutorial](https://joshua-fields.github.io/pemba/docs/guides/transactional-tutorial.html).
Review [alpha-to-stable migrations](https://github.com/Joshua-Fields/pemba/blob/v0.1.0/CHANGELOG.md),
including extensible Rust request types and `PendingRevision`. The caller owns
commit/rollback for foreign writes; resolve the token after successful commit and
use `AtLeast` for a subsequent read. Checks use engine connections and do not see
your uncommitted app transaction.

Explore policies in the [memory-only playground](https://joshua-fields.github.io/pemba/).
It cannot demonstrate real database transactions and is not a supported WASM
distribution. Read the [Rust API](https://docs.rs/pemba/0.1.0/pemba/),
[limits](https://joshua-fields.github.io/pemba/docs/guides/troubleshooting.html) and
[known differences](https://github.com/Joshua-Fields/pemba/blob/v0.1.0/crates/pemba-difftest/KNOWN_DIFFERENCES.md).
Choose a separate service such as SpiceDB for independent distributed operation or
features outside pemba's subset. [Issues](https://github.com/Joshua-Fields/pemba/issues)
and the [roadmap](https://github.com/Joshua-Fields/pemba/blob/main/ROADMAP.md) welcome
safe feedback; suspected vulnerabilities use
[SECURITY](https://github.com/Joshua-Fields/pemba/blob/v0.1.0/SECURITY.md) privately.
pemba is Apache-2.0 and credits Zanzibar and SpiceDB as design references, with no
SpiceDB code copied or translated; see [credits](https://github.com/Joshua-Fields/pemba/blob/v0.1.0/README.md#credits).

### Application data and permissions in one transaction

Creating a document often means writing two things: the document itself and a
relationship saying who can read it. When they live in separate systems, a failure
between writes needs recovery logic. pemba lets applications keep those writes in
one database transaction.

pemba is an embedded authorization engine written in Rust, with Python bindings.
It evaluates relationship-based policies in your process and stores relationships
in the database your application already uses. You can model document sharing,
groups and organization hierarchies using a strict subset of SpiceDB's schema
language. Checks, resource/subject lookups and explain traces share that model.

The [transactional tutorial](https://joshua-fields.github.io/pemba/docs/guides/transactional-tutorial.html)
contains runnable Rust and Python examples for both SQLite and Postgres. Each
example first creates an app document and grants its owner relation, then commits.
Assertions confirm that the app row exists, Anne can view it and Bob cannot.
The second transaction inserts another document and permission, deliberately
triggers a duplicate-primary-key error, and rolls the whole app transaction back.
Neither that document nor its permission survives. These are the tested examples,
not a demonstration of a transaction inside the browser playground.

The app owns the transaction. Rust's `write_in` and Python's `write(conn=...)`
join it; they do not commit it for you. They return `PendingRevision`, not proof
that a commit has happened. After a successful caller commit, resolve it and make
the subsequent check with `AtLeast` (Python `at_least=`). Native writes, where the
engine owns the transaction, return a committed `Revision`.

The stores differ before commit. SQLite's pending token already knows a number,
but that revision is not readable before commit; after rollback the number is
void, can be reused and cannot prove rollback. Postgres resolves the token after
commit, reports `RevisionPending` while the transaction is open and
`WriteRolledBack` after rollback. Portable code resolves only after successful
commit. Reads use engine-owned connections, so there is no promise of reading
your app transaction's uncommitted writes. An evaluation error is distinct from a
permission denial: errors return an error, and application code must handle them
explicitly rather than silently treating them as an authorization result.

The target 0.1.0 scope is Rust/CLI and Python, with memory, SQLite and synchronous
Postgres support. SQLite app and engine operations must use the same database and
one SQLite library in the process; the Python engine uses the host's `sqlite3`.
Postgres foreign writes support the documented synchronous drivers. Raw async
connections are deferred to T5.13 after stable. The browser playground builds
WASM for itself; there is no supported Node binding or general WASM package.

An embedded engine fits an app or a few services sharing a database. Choose a
separate authorization service such as SpiceDB when independent deployment,
distributed operation or capabilities outside pemba's subset are requirements.
There is no SpiceDB wire-API compatibility. Caveats/CEL, expiration, Watch and
server/distributed mode are outside the approved scope. Read the
[known differences](https://github.com/Joshua-Fields/pemba/blob/v0.1.0/crates/pemba-difftest/KNOWN_DIFFERENCES.md)
and [limits](https://joshua-fields.github.io/pemba/docs/guides/troubleshooting.html)
before adopting a policy; historical reads use the current schema and are bounded
by garbage collection. Postgres schema-rename recovery is not implemented.

Begin with [installation and quick starts](https://joshua-fields.github.io/pemba/docs/guides/installation.html),
then run the commit/rollback tutorial against disposable databases. Python's
post-publication install command is `python -m pip install pemba==0.1.0`; Rust
feature selection and CLI installation are in the guide. If upgrading from an
alpha, read the [migration notes](https://github.com/Joshua-Fields/pemba/blob/v0.1.0/CHANGELOG.md)
first, including the Rust extensible-type construction changes and Python's
removed `int(pending)`/index conversions. Use `.revision()` after commit or pass
the pending token to `at_least=`.

Use the [playground](https://joshua-fields.github.io/pemba/) to explore a synthetic
policy, the [Rust API](https://docs.rs/pemba/0.1.0/pemba/) for crate documentation,
and the [API specification](https://github.com/Joshua-Fields/pemba/blob/v0.1.0/docs/06-api.md)
plus installed Python `help(pemba.Engine)` for the binding contract. Public normal
bugs and requests go to [Issues](https://github.com/Joshua-Fields/pemba/issues);
suspected vulnerabilities go privately through
[SECURITY](https://github.com/Joshua-Fields/pemba/blob/v0.1.0/SECURITY.md).
The [roadmap](https://github.com/Joshua-Fields/pemba/blob/main/ROADMAP.md) separates
shipped scope from candidates, without promised dates. Support is best effort,
with no response SLA or guaranteed patch.

The design builds on Google's Zanzibar paper and SpiceDB's schema and behavior
as references; the implementation is original, with no SpiceDB source copied or
translated. See [credits](https://github.com/Joshua-Fields/pemba/blob/v0.1.0/README.md#credits),
[LICENSE](https://github.com/Joshua-Fields/pemba/blob/v0.1.0/LICENSE) and
[NOTICE](https://github.com/Joshua-Fields/pemba/blob/v0.1.0/NOTICE). pemba is Apache-2.0.
